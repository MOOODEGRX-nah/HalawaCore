# Contributing

Use an unprivileged Linux development environment and a virtual environment. Install `requirements-dev.txt`, then run `python -m pytest -q`. Run `node --check` on modified JavaScript modules. Exercise the UI through the same local FastAPI origin.

New topology support must come with synthetic sysfs fixtures and explicit evidence rules. Never add production CPU-number tables, invented cache sizes, marketing-name-to-core mappings, benchmark claims based on CPPC, or implicit affinity changes. Keep cache-sharing masks separate from die identifiers and preserve unknown data.

Affinity tests may modify only disposable subprocesses created by that test. Always restore and clean up. Exercise PID/TID reuse, per-task mask differences, permissions, hotplug and partial failures when changing task management. Do not run experiments on games, system services or the compositor during automated tests.

Document capabilities as designed, fixture-tested or physically tested. A fixture does not establish physical hardware compatibility. Add verified integration evidence before suggesting Proton/Wine launch configuration. Keep the frontend free of external telemetry and external assets.

Before a release, update CHANGELOG.md and docs/VALIDATION.md, capture real labeled screenshots, run the checks, and build the source archive with `python package.py`. Do not include data/, virtual environments, process exports or session tokens.
